# 安全自评报告（赛题口径）

> 对应赛题“权限分级实现说明 + 已知风险清单”。实现细节见 `CONTRACT.md`、`policy.py`、`rules/policy.rego`。

## 1. 权限分级实现

| 级别 | 范围 | 触发 | 实现 |
|---|---|---|---|
| 绿 | 只读查询：余额、流水、账单、持仓、知识咨询、主动提醒 | 不涉及资金/状态变更 | 直接执行；`policy.py` 矩阵 `green`；无确认 |
| 黄 | 小额办理：日累计 ≤1,000 元转账（新收款人单笔 ≤500 元）、取消订阅、风险测评、限额调整、虚拟卡 | 写操作但可逆/低金额 | 显式确认卡（金额、对象、后果、params_hash、token、倒计时） |
| 红 | 大额/不可逆：日累计 >1,000 元转账 / 新收款人 >500 元、挂失、解挂、赎回、还款、密码重置链接；单笔/计划硬上限 50,000 元 | 资金流出或不可逆 | 还款/信用卡还款：确认卡 → 强验证；其余红色：操作摘要 → 强验证（短信 + 人脸模拟因子）；密码修改恒拒绝 |

补充规则：

- 日累计 1,000 元、单笔 5 万元硬上限、新收款人 500 元、IM 渠道 300 元；
- 会话 LOCKED、风险分 >90、计划净流出超限 → deny；
- 注入/角色伪装/伪造系统消息/越权查询 → 前置 deny（`R-D-GUARD` / `R-D-INJECT`）；
- 咨询/否定句（“提前还款有违约金吗”“不要转账”）不进入办理计划；
- 模型只能产出候选计划，不能授权、不能直连工具；策略引擎最终裁决。

## 2. 安全机制证据

| 机制 | 证据 |
|---|---|
| 参数绑定 | 确认金额被改 → `E_PARAM`（params_hash 不匹配） |
| 一次性 token | 改一位 → `E_CONFIRM_TOKEN` |
| 审计哈希链 | 改一行 payload → `chain_ok=false` |
| 注入防护 | 红队 58/58 端到端拦截（`eval/cases/redteam.json`） |
| 权限边界 | 60/60（`eval/cases/permission.json`） |
| 会话防串话 | 设备指纹与会话绑定，换设备 409 |
| 已知绕过 | `KNOWN_BYPASS.md`：3 条检测漏检，但均未执行，靠策略兜底 |

安全证据面板：设置 → 安全，三个按钮现场复现 token/参数/审计篡改拦截。

## 3. 已知风险清单

| 风险 | 现状 | 缓解 |
|---|---|---|
| 非真实 KYC/活体 | 模拟实名 L2、设备指纹 | 明确演示边界；生产接公安/人脸 SDK |
| 强验证因子 | 短信码 + 人脸/设备模拟，演示码 123456 | 生产替换短信网关、活体、U 盾 |
| 复杂条件 DAG | 仅支持单条件单动作 | 文档标注；复杂场景转人工 |
| 其他红色动作确认卡 | 还款/信用卡已双闸，其余摘要+MFA | 下一版统一状态机 |
| 多轮指代 | 覆盖上个月/改金额/第一笔 | 通用 DST 待做 |
| 确认 token 下发前端 | 绑定 session/intent/params_hash/一次性/过期 | 生产改 HttpOnly Cookie/二次签名 |
| LLM 模式 | 默认关闭，需 Key，失败回退 | 零 Key 演示不受影响 |
| 知识/RAG | 关键词+向量混合，无文档解析/重排 | 文档标注边界 |
