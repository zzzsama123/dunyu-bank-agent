# P0 差距清单（诚实版）

> 结论：**没有全部做到。** 这是一个可运行的银行 Agent 仿真作品，不是生产级银行系统。
> 下表只区分"能演示/有实现/有测试"与"没有"，不把模拟能力写成真实能力。

## 一、P0 八项

| P0 项 | 状态 | 已有实现 | 明确缺口 |
|---|---|---|---|
| 1 身份与准入 | 部分 | 三级权限、OTP/人脸强验证模拟、客户号、设备指纹与会话绑定（换设备 409）、代办授权（范围/有效期/撤销）、审计 | 真实实名/KYC、活体人脸、公安/设备风控、跨客户号真实隔离仍为仿真 |
| 2 理解与交互 | 部分 | 离线 ASR、多轮上下文、指代消解、错字/口语归一、一键转人工、朗读；提示注入/角色伪装前置拦截；IM 文本确认/验证码闭环 | 真实 TTS 音色、打断抢话、方言声学、情绪识别、静默超时 |
| 3 查询类 | 基本覆盖 | 余额、流水、收支分析、理财持仓/收益、贷款进度/还款计划、信用卡账单、积分、网点排队、汇率/费率 | 真实核心系统对接、实时排队数据 |
| 4 办理类 | 部分 | 转账、还款（实际扣款+流水）、挂失、限额调整、虚拟卡、申购/赎回、风险测评（确认+有效期）、密码重置（仅一次性链接）；参数校验→风险→确认/强验证→回执/审计 | 开卡/开户预约、签约解约；密码修改恒拒绝（安全设计） |
| 5 知识与咨询 | 已实现（轻量） | 本地知识库：来源/生效/版本/编号；草稿→审批→发布；旧版自动下架；过期定时下架；便携版 BGE 向量+关键词混合检索 | 无文档解析/切分/重排；无真实内容审核平台 |

| 8 运营管理 | 部分 | 全量审计索引、指标看板（会话/trace/事件/工具/好评差评/知识）、badcase 归集、知识状态 | 灰度/回滚、AB 实验、prompt/知识版本审批发布、成本核算 |

## 三、本轮新增（可演示）

1. 只读查询：贷款进度/还款计划、信用卡账单、积分、网点排队、汇率；
2. 知识库：来源、生效日期、版本、过期下架、知识编号；
3. 主动服务：`/v1/proactive` + "今天有什么提醒"；
4. 人机协同：转人工生成工单 `T...`，带交接摘要；
5. 运营：`/v1/metrics` + 设置-运营看板 + 回复「有用/没帮上」badcase 归集；
6. 交互：回复「朗读」、本地知识引用。

## 四、下一步建议（按风险/收益）

1. **身份与授权**：设备指纹 + 代办授权（P0 最高风险缺口）；
2. **办理闭环**：还款、风险测评、密码重置（带确认/回执）；
3. **知识工程**：向量检索 + 版本审批 + 过期任务；
4. **人机协同**：工单流转状态、坐席摘要卡片；
5. **运营**：灰度开关与 AB 实验框架。

> 所有资金与客户数据均为合成数据；不连接真实银行系统，不产生真实资金变动。

## 五、公开的残余风险

检测层已知 3 条绕过（口头授权/测试文本/角色扮演），均未执行，靠策略强验证兜底；详见 `docs/KNOWN_BYPASS.md` 与 `eval/cases/redteam_known_bypass.json`。

## 六、已知能力边界（实测）

- 条件式只支持“如果(本月/上月)账单超 X 就转 Y 给 Z”这一种；其他条件式仍不支持；
- 多轮“那上个月呢 / 改成200”已打通；“第一个退掉”目前给指认提示，未自动执行；
- 还款已改成“金额确认卡 → 强验证”双闸；其他红色动作仍是“摘要 + 强验证”单闸；
- 信用卡还款尚未闭环；账单 Excel 导出已支持生成链接。

## 七、V3 复核补充

- 复合句“还房贷 + 查余额”已按顺序执行；
- 条件式会把账单结果与条件写进回复，但**没有把 query 节点真实加入 plan DAG**，仍是预计算；
- 补偿演示：设置环境变量 `DEMO_FAIL_TOOL=create_standing_plan` 后确认生日计划，可看到冻结被逆序释放；
- 多因子仍是模拟短信 + 模拟人脸，生产替换口径见 `docs/STEPUP.md`。
